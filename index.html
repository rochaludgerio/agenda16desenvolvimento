01 • Fundamentos

O que são Web Services?

Web Service é uma interface desenvolvida para permitir a comunicação entre aplicações por meio de uma rede. O HTTP é um dos protocolos mais utilizados nessa comunicação.

🔗

Integração

Permite que sistemas diferentes troquem informações sem precisarem ser construídos na mesma linguagem ou plataforma.

🌐

Comunicação em rede

Uma aplicação envia uma requisição a um serviço e recebe uma resposta com os dados solicitados.

♻️

Reutilização

Um serviço pode oferecer funcionalidades para várias aplicações, evitando a reescrita de códigos e regras.

Ideia central: em vez de cada sistema manter isoladamente todas as informações, os serviços permitem compartilhar dados e funcionalidades de maneira organizada.
02 • Padrões e formatos

Tecnologias envolvidas

A apostila apresenta três abordagens para Web Services: SOAP, REST e XML-RPC. Também destaca o HTTP e o XML no contexto de XML Web Services.

SOAP

Simple Object Access Protocol

Protocolo de troca de mensagens estruturadas em XML, utilizado para permitir a comunicação entre aplicações por meio de protocolos como HTTP.

REST

Representational State Transfer

Estilo de arquitetura baseado no HTTP. Não impõe um formato único para a mensagem; orienta o comportamento dos componentes envolvidos.

XML-RPC

Chamada remota de procedimento

Especificação que permite executar operações entre softwares e transmitir estruturas de dados, mantendo a proposta de simplicidade.

HTTP

Protocolo de comunicação utilizado para enviar requisições e receber respostas entre cliente e serviço.

XML

Formato de marcação que organiza dados em elementos e permite representar informações estruturadas.

A apostila também aponta dois alicerces do XML Web Service: comunicação pelo protocolo HTTP e envio/recebimento de dados no formato XML.
03 • Funcionamento

Como acontece a comunicação?

Uma aplicação cliente solicita uma informação. O Web Service processa a solicitação e devolve uma resposta que poderá ser utilizada pela aplicação.

1. ClienteUsuário solicita uma ação
→
2. RequisiçãoAplicação envia os dados via rede
→
3. ServiçoProcessa a solicitação
→
4. RespostaRetorna os dados
→
5. AplicaçãoTrata e apresenta o resultado

Cliente e provedor

O cliente inicia a solicitação; o provedor disponibiliza o serviço e responde ao pedido.

Comunicação entre serviços

Como ilustra o diagrama da página 3 da apostila, um serviço pode atuar como cliente em uma interação e como servidor em outra. A comunicação pode ocorrer entre serviços, não apenas no modelo tradicional cliente-servidor.

04 • Demonstração prática

Consumindo um Web Service: consulta de CEP

O material didático utiliza o ViaCEP para buscar um endereço a partir do CEP. A resposta pode fornecer logradouro, complemento, bairro, cidade e estado.

Integração com API externa

Como o site da Enlatados Juarez utiliza um serviço externo?

O site não precisa possuir uma base própria de endereços. Ele solicita essa informação à API pública do ViaCEP, que é externa à aplicação, e utiliza os dados recebidos no cadastro.

Não é necessário criar um banco de dados para demonstrar o consumo da API: a atividade principal é fazer a requisição, receber a resposta e utilizar os dados. Um banco seria uma ampliação, caso a empresa também desejasse armazenar permanentemente os cadastros.

O que acontece por trás da tela?

  1. O usuário informa o CEP.
  2. A aplicação organiza o valor e monta a URL do serviço.
  3. Uma requisição é enviada ao ViaCEP.
  4. O serviço retorna os dados do endereço.
  5. A aplicação interpreta a resposta e exibe os campos.
Esta demonstração usa a resposta JSON do endpoint público do ViaCEP diretamente no navegador. A apostila ensina a mesma ideia de consumo usando PHP e resposta XML.

Exemplo da apostila: requisição em PHP com XML

A função abaixo remove caracteres que não sejam números, monta a URL do ViaCEP no formato XML, faz a requisição e retorna o conteúdo recebido.

function get_endereco($cep)
{
    // Mantém apenas os números do CEP
    $cep = preg_replace("/[^0-9]/", "", $cep);

    // Monta a URL do Web Service
    $url = "https://viacep.com.br/ws/$cep/xml/";

    // Faz a requisição e recebe o XML
    $xml = simplexml_load_file($url);

    return $xml;
}

Exemplo de resposta XML

<xmlcep>
  <cep>01001-000</cep>
  <logradouro>Praça da Sé</logradouro>
  <complemento>lado ímpar</complemento>
  <bairro>Sé</bairro>
  <localidade>São Paulo</localidade>
  <uf>SP</uf>
</xmlcep>
Observações técnicas: a apostila usa http://, mas o ViaCEP atende em https://, que é o recomendado. Para o simplexml_load_file() aceitar uma URL, o PHP do servidor precisa estar com allow_url_fopen ativo (no XAMPP/Apache já vem habilitado).

Tratando CEP inexistente

Se o CEP não existir, o serviço devolve um erro e o código da apostila não percebe. Um teste simples evita mostrar campos vazios ao usuário:

$endereco = @get_endereco($_POST["txtCEP"]);

if ($endereco === false || isset($endereco->erro)) {
    echo "CEP não encontrado. Confira os números digitados.";
} else {
    echo "Rua: $endereco->logradouro";
}
Consolidação dos dados: após receber o XML, o PHP acessa os elementos desejados (como $endereco->logradouro e $endereco->uf) e os utiliza para preencher os campos do cadastro.

Código do cadastro com Session (solução da apostila)

Este é o núcleo do arquivo VoceNoComando.php. O formulário usa method="post" e action="#", ou seja, envia os dados para a própria página.

<?php
function get_endereco($cep) { /* consulta o ViaCEP (mostrada acima) */ }

if (!isset($_SESSION)) { session_start(); }

// 1) Inicializa as variáveis de sessão vazias
$_SESSION["nome"] = "";   $_SESSION["cep"] = "";
$_SESSION["logradouro"] = "";  $_SESSION["numero"] = "";
$_SESSION["bairro"] = ""; $_SESSION["cidade"] = ""; $_SESSION["estado"] = "";

// 2) Se o botão "Buscar Endereço" foi clicado, consulta o Web Service
if (isset($_POST["btnBuscar"])) {
    $endereco = get_endereco($_POST["txtCEP"]);

    // Dados digitados pelo usuário
    $_SESSION["nome"]   = $_POST["txtNome"];
    $_SESSION["cep"]    = $_POST["txtCEP"];
    $_SESSION["numero"] = $_POST["txtNumero"];

    // Dados vindos do Web Service (convertidos para texto)
    $_SESSION["logradouro"] = (string)$endereco->logradouro;
    $_SESSION["bairro"]     = (string)$endereco->bairro;
    $_SESSION["cidade"]     = (string)$endereco->localidade;
    $_SESSION["estado"]     = (string)$endereco->uf;
}
?>

<!-- 3) Cada campo exibe a variável de sessão correspondente -->
<input name="txtLogradouro" value="<?php echo $_SESSION["logradouro"]; ?>">

Por que (string)?

O simplexml devolve objetos XML. Converter para texto garante que a Session guarde apenas o valor, pronto para ir ao campo do formulário.

O que é consolidar dados?

Reunir no mesmo lugar o que o usuário digitou (nome, número) e o que o serviço retornou (rua, bairro, cidade, UF), formando um cadastro completo.

Referência: Agenda 16, páginas 8 a 14. A apostila apresenta o formulário de cadastro e explica o uso de variáveis de sessão para manter os dados no preenchimento.

06 • Cenário empresarial

Como isso pode ajudar a Enlatados Juarez?

Em uma empresa com diferentes áreas e aplicações, a integração por serviços pode reduzir lançamentos repetidos e manter informações disponíveis aos sistemas que precisam delas.

🛒

E-commerce e estoque

O sistema de vendas consulta a disponibilidade de produtos antes de confirmar um pedido.

💳

Vendas e financeiro

Uma aplicação pode encaminhar informações de pedidos para apoiar processos de cobrança e conciliação.

🚚

Logística

Dados de endereço e entrega podem ser compartilhados entre o cadastro, o pedido e o sistema logístico.

Exemplo hipotético: quando uma venda é realizada no e-commerce, um serviço poderia disponibilizar os dados do pedido ao estoque e à logística. A implementação dependeria das regras, sistemas e requisitos de segurança da empresa.

08 • Encerramento

Conclusão

Web Services são uma solução importante para integrar aplicações, compartilhar dados e reaproveitar funcionalidades. Com HTTP, formatos como XML e abordagens como SOAP, REST e XML-RPC, sistemas distintos podem trocar informações de forma estruturada.
